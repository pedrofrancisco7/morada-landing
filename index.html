Engineering decisions

Trade-offs,
documented.

Every non-obvious choice has a reason. Here are four that shaped the architecture.

Decision 01
Supabase Auth over Azure AD B2C
Azure AD B2C requires an Azure subscription with tenant licensing that conflicts with the whitelabel model — each condominium would need its own tenant. Supabase Auth gives per-project isolation with custom invite codes built-in, at zero marginal cost per tenant.
→ Supabase: simpler, cheaper, tenant-native
Decision 02
Railway over Azure App Service
Azure App Service is the natural choice for a .NET developer, but at solo-project scale the cognitive overhead of Azure billing, resource groups and networking is disproportionate. Railway gives a production-grade URL with zero infra config, preserving focus for product work.
→ Railway: right-sized for the stage
Decision 03
Turborepo monorepo from day one
Three apps sharing types and design tokens need a monorepo to stay in sync. Starting with separate repos and migrating later is painful. Turborepo with pnpm workspaces was set up in Sprint 0 so shared-types and ui-tokens are enforced across mobile, web and API from the start.
→ Monorepo: consistency before velocity
Decision 04
PR discipline even as solo dev
Every feature merge goes through a pull request with CI green — no exceptions, even with no teammates. This creates a linear, reviewable Git history, forces atomic commits, and mirrors the workflow expected in any professional team. It's also the single fastest way to build a portfolio that proves process maturity.
→ PRs: the habit that compounds
